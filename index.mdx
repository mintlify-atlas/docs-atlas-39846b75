## Install in three minutes

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/Nmor/the-claude-council.git
    cd the-claude-council
    ```
  </Step>
  <Step title="Run the installer">
    <CodeGroup>
    ```bash macOS / Linux / WSL2
    ./bootstrap/install.sh
    ```
    ```powershell Windows (PowerShell)
    Set-ExecutionPolicy -Scope Process Bypass
    .\bootstrap\install.ps1
    ```
    </CodeGroup>
  </Step>
  <Step title="Verify the install">
    <CodeGroup>
    ```bash macOS / Linux / WSL2
    ./bootstrap/verify.sh
    ```
    ```powershell Windows (PowerShell)
    .\bootstrap\verify.ps1
    ```
    </CodeGroup>
  </Step>
  <Step title="Open any project">
    Open any project in a Claude Code-compatible IDE. The Council activates on the next prompt.
  </Step>
</Steps>

## The 16-division structure

The Council speaks from five always-active Core Divisions and eleven Extended Divisions that auto-fire on matching triggers.

| Division | Agents | Trigger |
|---|---|---|
| **1. Architecture & Planning** | `architect`, `planner` | Every task |
| **2. Implementation & Build** | build resolvers, `refactor-cleaner`, `database-reviewer` | Every code change |
| **3. Quality & Review** | `code-reviewer`, language reviewers, `doc-updater` | Every code/docs change |
| **4. Security** | `security-reviewer` | Every task — VETO authority |
| **5. Testing & QA** | `tdd-guide`, `e2e-runner` | Every code change |
| **6–16. Extended Eleven** | compliance, UX, ops, data, finance, risk, strategy, people, ESG, ethics, comms | Trigger-matched |

<Note>
The Council scales its review to the work. Routine tasks get concise, relevant guidance — not repeated speeches. Full deep-review templates are available for high-risk or explicitly complex work.
</Note>

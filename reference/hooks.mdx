Hooks turn rules into machinery. Where a rule document says "never do X," a hook makes it impossible to silently drift past that rule — they run automatically at lifecycle events, inspect the actual tool call or file diff, and exit non-zero when a banned pattern appears. If a banned pattern lands in a `PostToolUse` diff, the hook blocks the edit and returns the error to the agent in the same turn, which forces a corrective edit before any other work continues. The Council ships 25+ hook scripts covering every lifecycle event Claude Code exposes.

## Deep dive: `post-edit-no-discards.js`

`post-edit-no-discards.js` is the zero-tolerance mechanical coding rule enforcer. It runs after every `Edit` or `Write` tool call and exits with status 2 if the resulting file contains any banned pattern. Claude Code surfaces the stderr report to the agent in the same turn, forcing a corrective edit before any other work continues.

The hook's rule manifest lives in `scripts/hooks/lib/no-discards-rules.js`. Patterns enforced include:

| Rule ID | Level | What it checks |
| --- | --- | --- |
| `underscore-discard` | block | `_, ` / `, _ :=` / `_ =` return-value discards in Go, TypeScript/JavaScript, and Python |
| `expr-statement-discard` | block | Bare `find()`/`fetch()`/`lookup()`/`parse()`/`compute()`/`calculate()`/`query()` calls whose return value is dropped |
| `placeholder-marker` | block | `TODO`, `FIXME`, `XXX`, `BUG`, `HACK`, `KLUDGE`, `WORKAROUND`, `NOTE` markers in production source, Markdown, and CSS |
| `scaffold-deferral` | block | Comments containing `scaffold only`, `stub for now`, `placeholder implementation`, `implement later` in production code |
| `suppression` | block | `// nolint`, `// eslint-disable`, `// @ts-ignore`, `// @ts-expect-error`, `# noqa`, `# type: ignore`, `# pragma: no cover`, `# rubocop:disable` |
| `task-pointer` | block | Comments that reference plan IDs (`plan B2`, `Phase 3`, `GAP-9`, `Wave A`, `P11.W2.G2`) rather than stating the WHY |
| `raw-color` | block | Hex (`#fff`), `rgb()`, `hsl()`, `oklch()` literals in UI components and CSS outside a `--token` definition |
| `console-log` | block | `console.log(` in production JavaScript/TypeScript source |
| `hardcoded-secret` | block | API key prefixes (`sk-proj-`, `sk_live_`, `ghp_`, `xoxb-`, `AKIA`), AWS secrets, Bearer JWT tokens, and PEM private key headers |
| `go-test-naming` | block | Go test functions named `Test_Foo_Bar` instead of using `t.Run` subtests |
| `merge-conflict` | block | Leftover `<<<<<<<` / `>>>>>>>` conflict markers in any file |
| `empty-catch` | block | Empty `catch` blocks in JavaScript/TypeScript that swallow errors silently |
| `silent-catch` | block | `.catch(() => {})` or `.catch(() => null)` patterns that discard the error |
| `silent-except` | block | Python `except:` or `except Exception:` blocks whose body is only `pass` or `...` |
| `important` | warn | `!important` in CSS/UI files (soft warning — bypasses design tokens) |
| `size-budget` | warn | Files that exceed their own declared `// Size budget:` comment |
| `file-too-large` | warn | Production source files past 800 lines with no declared budget |

The hook never scans files under `.claude/scripts/hooks/` itself — the enforcement tooling necessarily contains the banned patterns as definitions and documentation.

**Operator override**: `export CLAUDE_NO_DISCARDS_HOOK=off` skips the check. Intended for bulk-import of legacy code. The agent must never set this variable itself.

## Wiring: how hooks are registered in `settings.json`

Hooks are declared in `~/.claude/settings.json` under the `hooks` key. Each entry maps a lifecycle event to an array of matchers and their associated commands:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Agent|Task",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$HOME/.claude/scripts/hooks/model-ladder-gate.js\""
          }
        ]
      },
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$HOME/.claude/scripts/hooks/dev-server-gate.js\""
          },
          {
            "type": "command",
            "command": "node \"$HOME/.claude/scripts/hooks/commit-gate.js\""
          }
        ]
      },
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$HOME/.claude/scripts/hooks/suggest-compact.js\""
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$HOME/.claude/scripts/hooks/post-edit-no-discards.js\""
          }
        ]
      }
    ],
    "PreCompact": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$HOME/.claude/scripts/hooks/pre-compact-council-brief.js\""
          }
        ]
      }
    ],
    "SessionStart": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$HOME/.claude/scripts/hooks/session-start.js\""
          }
        ]
      }
    ],
    "Stop": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$HOME/.claude/scripts/hooks/docs-sync-gate.js\"",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

The `matcher` field is a pipe-separated list of tool names, or `*` for all events. Multiple hook arrays for the same event and matcher run in order. A hook that exits non-zero blocks the tool call for `PreToolUse`, or forces Claude to continue and address the issue for `PostToolUse` exit 2.

<Warning>
The Council's quality gates are **mechanical, not advisory**. Fourteen hook-enforced gates fire automatically at lifecycle events. When a gate exits non-zero, the tool call is blocked or Claude is forced to fix the violation before continuing — there is no path to silently drift past a rule. Do not attempt to set override environment variables from within agent code; only the operator (you, in your shell) can set bypass variables such as `CLAUDE_NO_DISCARDS_HOOK=off`, `CLAUDE_PUSH_AUTHORIZED=yes`, or `CLAUDE_COMMIT_GATE=off`.
</Warning>

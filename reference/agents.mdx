The Claude Council ships 39 specialist agents organized across 16 divisions. Agents are delegatable specialists — the Council protocol automatically delegates to them when their expertise is needed. Each agent is declared in its own Markdown file under `~/.claude/agents/` with frontmatter defining its `name`, `description`, `tools`, and `model`. Touching certain files auto-engages the relevant agents silently, with no slash command or explicit delegation needed.

## Principal-level template

Every agent in the Council meets the principal-level bar defined in `principal-level-mandate.md`. Each agent file contains all 11 of the following elements:

1. **Frontmatter** — `name`, `description`, `tools`, `model`
2. **Identity + mission** — a principal-level statement of what the agent owns
3. **Global rules enforced** — explicit cross-references to the rules the agent enforces
4. **Auto-fire triggers** — file globs, keywords, and scope conditions that cause automatic engagement
5. **Decision authority** — veto / casting vote / advisory, with rationale for the tier
6. **Review checklist or workflow** — explicit checks with severity labels
7. **Standards cited** — version and section numbers (e.g., OWASP Top 10 2021 A01, WCAG 2.2 §1.4.3)
8. **Output shape** — structured findings, not narrative prose
9. **Anti-patterns to reject** — concrete bad patterns with named alternatives
10. **Pairing model** — which other agents this agent works with and in what order
11. **When to escalate to user** — explicit triggers for surfacing decisions that require human judgment

## Model selection

Each agent's role maps to a capability-aware ladder. The Council spawns the best model available in the install: **Fable → Opus → Sonnet → Haiku** (defaulting to `{opus, sonnet, haiku}` when Fable is not present). The model listed in each table below is that agent's default for a direct spawn — its ladder floor.

| Tier | Use cases |
| ---- | --------- |
| **fable** | Hardest / long-horizon / novel non-security work, on installs where Fable is available |
| **opus** | Deep reasoning, review, planning, security, compliance, ethics — quality and broad coverage |
| **sonnet** | Mechanical build and compile fixes, narrow-scope reviewers, verification-loop agents |
| **haiku** | Mechanical doc work — codemaps, README maintenance |

## Veto authority summary

The following agents hold hard veto authority within their scopes. A veto blocks the change from proceeding — advisory agents from other divisions cannot override it.

| Agent | Veto scope |
| ----- | ---------- |
| `security-reviewer` | BLOCKER-severity security findings |
| `compliance-reviewer` | Any regulatory compliance finding |
| `payments-reviewer` | Payments, escrow, open-banking scope |
| `health-reviewer` | Healthcare, clinical data, FDA SaMD scope |
| `education-reviewer` | Edtech, student-data, FERPA/COPPA scope |
| `risk-reviewer` | Out-of-scope blast-radius findings |
| `ai-ethics-reviewer` | AI safety, fairness, and bias findings |

All other agents — including `ux-reviewer`, `accessibility-reviewer`, `ops-reviewer`, `data-reviewer`, `finance-reviewer`, `strategy-reviewer`, `people-reviewer`, `esg-reviewer`, `comms-reviewer`, and all build resolvers — operate in **advisory** mode. Their findings are surfaced as recommendations rather than hard blocks.

## Parallel agent execution

Per the Council's standing directive, agents run at most **2 in parallel**. Heavier fan-out is sequential to keep output legible and the user's review surface tractable.

When agents are dispatched in parallel, they are sent in a single message with multiple tool calls. When agents depend on each other's output — for example, `code-reviewer` reviewing the result of `build-error-resolver`'s fix — they run sequentially.

## Auto-delegation via auto-skills

The `auto-skills.md` rule maps file types to both skills and agents. When you touch a file, matching agents auto-engage silently with no slash command or explicit delegation required.

For example, touching a `*.go` file auto-engages `go-reviewer`, `go-build-resolver`, `tdd-guide`, and `security-reviewer`. Touching a `payments/charge.ts` file auto-engages `payments-reviewer`, `compliance-reviewer`, `security-reviewer`, `finance-reviewer`, `risk-reviewer`, and `code-reviewer`.
